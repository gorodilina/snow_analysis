# Анализ снежной обстановки (Streamlit + Google Earth Engine)

Веб-интерфейс для просмотра спутниковых снимков Sentinel-2 / Landsat 8–9 вдоль загруженных GPX/KML-треков. По умолчанию показываются пример трека `data/default_route.kml` (798 вершин) и 28 точек из `data/default_points.kml`.

## Функции

- **Конкретный снимок:** спутник → год и месяц → «Найти доступные даты» → дата → конкретная сцена или мозаика только этого календарного дня. На карте показана **фактическая дата съёмки**; несколько сцен одного дня не смешиваются с другими днями.
- **Медианная мозаика:** выбор начального дня и длины интервала **2–9 календарных дней с шагом 1 день**, включая первый и последний день. Например, 1 июня + 5 дней → 1–5 июня. Число найденных **спутниковых сцен показывается сразу при выборе интервала**, до построения мозаики, а затем повторяется в подписи к готовому снимку. Это количество гранул/сцен GEE, а не число уникальных дат и не гарантированное число облачно-свободных снимков.
- Одно окно позволяет загрузить **любое количество KML/GPX файлов одновременно** (плюс CSV для точек). Треки из всех файлов объединяются; при наличии пользовательских треков они заменяют пример. Исходные **28 точек** загружаются по умолчанию, пользовательские точки из файлов и вручную добавляются к ним. Видимость точек и подписей отдельно регулируется в «Слоях карты».
- Внутри **«Слои карты»** включаются/выключаются и регулируется непрозрачность снимка и других растровых слоёв; подписи точек регулируются там же. **В боковой панели нет регулировок прозрачности и подписей.**
- **Несколько независимых спутниковых слоёв.** Каждое нажатие «Добавить снимок как слой» или «Добавить медиану как слой» создаёт отдельный слой RGB **без маски облаков**. Количество слоёв не ограничено счётчиком в интерфейсе; реальное ограничение определяется производительностью браузера, квотами Earth Engine и лимитом размера сессии.
- **Короткие подписи:** `S2 · 15.06.25 08:31` (отдельная сцена), `L8/9 · 15.06.25 · день` (мозаика сцен за один день), `S2 · 01–05.06.25 · мед.` (медиана). Если открыто несколько сцен с одинаковым временем, они имеют разные внутренние ID.
- **Управление:** любой снимок можно показать/скрыть, изменить его непрозрачность и удалить по кнопке × прямо в «Слоях карты». Новые снимки располагаются поверх старых; все снимки располагаются под **границей снега, изотермами, треком и точками**.
- **Аналитические слои:** у каждого изображения своя граница снега NDSI и изотермы −5/0/+5/+10 °C. Все контуры включаются общим переключателем; их прозрачность следует прозрачности соответствующего снимка.
- Подложки: Esri World Topo Map, OpenTopoMap, OSM, Esri Imagery. **Google Terrain** доступен дополнительно через официальный Google Maps **Map Tiles API**, если задан `GOOGLE_MAPS_API_KEY`. Без ключа пункт виден как недоступный; остальные карты работают без него. Для Google Terrain нужен отдельный API-ключ Google Maps Platform, включённый Map Tiles API и биллинг. <https://developers.google.com/maps/documentation/tile/get-api-key>. В отличие от GEE service account, ключ Map Tiles API используется браузером при получении тайлов; ограничьте ключ только необходимым API и разрешёнными источниками, настройте квоты.

## Сохранение исследования по ссылке (новая функция)

Без регистрации: в разделе **«5. Сохранение по ссылке»** нажмите **«Сохранить и получить ссылку»**. Вы получите URL вида `https://<имя-приложения>.streamlit.app/?session=<случайный-токен>`. Откройте эту ссылку позже, чтобы восстановить:

- объединённые треки и точки (не сами исходные бинарные файлы);
- **все** добавленные сцены Sentinel-2/Landsat и медианы: порядок, спутник, точные даты, ID каждой сцены, длительность медианы;
- видимость и непрозрачность каждого снимка, видимость верхних слоёв, подложку, центр/масштаб карты;
- название исследования и заметки.

После первого сохранения правки записываются автоматически, включая удаление снимков и настройки карты. Снимки повторно обрабатываются на Earth Engine при открытии ссылки: истекающие tile URL не сохраняются.

### Экспорт и восстановление ZIP
В разделе «5. Сохранение по ссылке» есть **«Скачать исследование (ZIP)»**, работающая и без Supabase. В ZIP находятся `project.json` (все слои с параметрами, треки, точки, заметки, карта), `tracks.geojson`, `points.geojson`, `manifest.json` и `README.txt`. Спутниковые растровые данные не архивируются. В разделе «1. Трек и точки» ZIP можно вернуть через **«Восстановить проект из ZIP»**. При импорте создаётся локальная копия исследования, не перезаписывающая прежний облачный URL; для её долговременного облачного хранения создайте новую ссылку.

**Безопасность:** ссылка является ключом доступа к исследованию. Любой, кому вы её передадите, сможет **просмотреть и редактировать** содержимое. Не добавляйте чувствительные данные в заметки и не публикуйте ссылку, если нужна приватность. Пока нет авторизации, прав только на чтение и истории версий отдельных исследований. Последний сохранивший изменения побеждает при одновременном редактировании из нескольких вкладок.

### Один раз подключить базу Supabase

Ключ Earth Engine для этого не подходит. Создайте **Supabase-проект** на https://supabase.com/, затем:

1. В Supabase **SQL Editor** выполните файл `supabase_setup.sql`. Он создаст таблицу `public.snow_sessions` с включённой RLS. Для `anon` и `authenticated` прямой доступ закрыт.
2. В **Project Settings → API Keys** возьмите **secret key (`sb_secret_...`)**, а также URL проекта. Legacy `service_role` тоже поддерживается. **Никогда не вставляйте secret key в GitHub и браузер.**
3. В Streamlit Cloud → **App settings → Secrets** добавьте к существующим `GEE_PROJECT` и `GEE_SERVICE_ACCOUNT`:

```toml
SUPABASE_URL = "https://your-project.supabase.co"
SUPABASE_SECRET_KEY = "sb_secret_YOUR_SERVER_ONLY_SECRET"
```

4. Перезапустите приложение. В разделе «Сохранение по ссылке» появится кнопка. Если Supabase ещё не настроен, обычный просмотрщик снимков продолжает работать, но постоянные ссылки отключены.

**Тестовая версия:** ветка `feature/shareable-research-sessions` для тестового Streamlit-приложения. Версия до нескольких снимков отдельно сохранена в ветке `backup-before-multilayer-export-2026-11-17`. Рабочая основная ветка `main` остаётся нетронутой.

### Изменения загрузчика

Теперь есть **одно окно загрузки нескольких KML/GPX/CSV**. Если загружаются пользовательские треки, демонстрационный маршрут и его 28 точек исчезают. Если загружаются только точки, демонстрационные 28 точек сохраняются. Видимость точек и их подписей настраивается в «Слоях карты». В режиме медианы количество найденных сцен подписывается обычным серым текстом, без синей плашки.


## Галерея областей карты, PDF и GeoTIFF

### Отдельные контуры на каждом снимке

Каждый спутниковый снимок или медиана имеет собственные **границу снега NDSI и изотермы ERA5-Land**. В «Слоях карты» единый переключатель **«Граница снега + изотермы (все снимки)»** включает или отключает их на ВСЕХ снимках. Если переключатель выключен, для экономии запросов Earth Engine контуры не запрашиваются. Внутри стопки порядок такой:

**RGB снимка A → его снег/изотермы → RGB снимка B → его снег/изотермы → ... → трек/точки/подписи.**

При изменении непрозрачности снимка соответствующие контуры меняют её пропорционально. Скрытый снимок скрывает и свои контуры.

### Галерея

1. На карте нажмите **«Выделить область»**, протяните прямоугольник мышью и выберите PNG либо JPG.
2. Нажмите **«В галерею»**. Сохраняется видимый фрагмент карты: текущие снимки, их непрозрачность, видимые линии и трек. Область карты сохраняется как WGS84 `[west,south,east,north]`.
3. В боковой панели **«5. Галерея выбранных областей»** можно листать снимки, задавать необязательные название/заметку, удалять и скачивать:
   - **ZIP**: только PNG/JPG-файлы галереи;
   - **PDF**: по одному изображению на странице, с названием и заметкой.
4. В экспандере **«Резервная копия всего исследования (ZIP)»** можно дополнительно сохранить всю структуру исследования и фотографии для последующего восстановления в приложении.

**Ограничение скриншотов:** захват происходит в браузере через `html2canvas`. Некоторые поставщики картографических подложек не разрешают CORS, из-за чего их тайлы могут отсутствовать на PNG/JPG. Проверьте снимок в галерее перед экспортом. Это не относится к GeoTIFF. Максимальный размер изображения — 2 МБ, максимальное число элементов галереи — 250; снимки ограничиваются ~3 мегапикселями.

### Новая настройка Supabase Storage

После основного `supabase_setup.sql` **однократно выполните** в Supabase SQL Editor **`supabase_gallery_setup.sql`**. Он создаст **приватный** bucket `snow-gallery` (image/png и image/jpeg; до 2 МБ на фото). Файлы хранятся там; таблица `snow_sessions` содержит только метаданные галереи и ссылки на закрытые объекты. Уже используемые `SUPABASE_URL` и `SUPABASE_SECRET_KEY` подходят и для файлов. Не добавляйте новые ключи в GitHub.

Если хранилище изображений недоступно, фотографии остаются в памяти текущей вкладки и могут выгружаться, но **не гарантируется восстановление по ссылке**: приложение предупреждает о неполном сохранении.

### GeoTIFF для выбранной области

После выбора области на карте откройте **«7. Геопривязанный GeoTIFF»**, выберите исходный снимок и разрешение. Можно также выбрать прямоугольник из ранее сохранённой фотографии галереи. Экспортируется **4-канальный** геопривязанный GeoTIFF с численными значениями отражения (`red,green,blue,swir`) выбранного снимка или медианы. **Это не скриншот**: картографические подложки, визуальные контуры, трек и пользовательские надписи не входят в GeoTIFF. Для Sentinel-2 рекомендовано 20 м (SWIR), для Landsat 8/9 — 30 м. По лимитам `getDownloadURL` Earth Engine один экспорт не должен превышать 32 МБ; крупные области следует уменьшать или выгружать с более грубым разрешением.

### Предыдущие версии для отката

- `main` — исходное рабочее приложение, остаётся неизменённым;
- `backup-before-gallery-2026-11-17` — тестовая версия со многими снимками, но ещё без галереи;
- `feature/shareable-research-sessions` — тестовое приложение (новые изменения сначала проверяются в отдельной feature-ветке).

## Быстрый запуск локально

```bash
python -m venv .venv
# Windows:
.venv\Scripts\activate
# macOS/Linux: source .venv/bin/activate
pip install -r requirements.txt
```

Далее настройте Google Earth Engine для вашего Google Cloud проекта (проект должен быть зарегистрирован в Earth Engine, API включён):

```bash
earthengine authenticate
```

Скопируйте `.streamlit/secrets.example.toml` в `.streamlit/secrets.toml` и установите `GEE_PROJECT`.

```bash
streamlit run app.py
```

Без авторизации Earth Engine маршруты и точки всё равно отображаются, но поиск снимков недоступен.

## Развёртывание в Streamlit Community Cloud

1. Выберите GitHub-репозиторий `gorodilina/snow_analysis`, ветку `main` и путь `app.py`.
2. В Secrets задайте `GEE_PROJECT`, а также `GEE_SERVICE_ACCOUNT` как многострочную строку с **полным JSON ключом сервисного аккаунта**, либо `gee_service_account` в виде TOML-секции с полями ключа. **Дополнительно (по желанию)** можно указать `GOOGLE_MAPS_API_KEY` для слоя Google Terrain; это другой ключ, не имеющий отношения к авторизации Earth Engine.
3. Предоставьте сервисному аккаунту необходимые разрешения Earth Engine и используйте зарегистрированный Cloud-проект. Нигде в GitHub не размещайте ключ сервиса, токены или `secrets.toml`.
4. Перезапустите приложение.

Официальная инструкция: https://developers.google.com/earth-engine/guides/service_account

## Формат файлов

- KML: LineString и Point (в том числе внутри MultiGeometry).
- GPX: `<trk>`, `<rte>` и `<wpt>`; трек может состоять из нескольких сегментов.
- CSV (точки): `name,lat,lon` в UTF-8. Широта/долгота в WGS84.
- Максимальный размер загружаемого файла: 15 МБ; для треков максимум 100 000 вершин.

## Методологические ограничения

- NDSI (`(green - SWIR)/(green + SWIR)`, порог 0,40) показывает *снег и лёд*, а также подвержен ошибкам из-за затенения, облаков и ярких поверхностей. Это не глубина снега и не гарантированная снеговая линия.
- **RGB-изображения отображаются без маски облаков**; отдельного слоя с замаскированным снимком больше нет. При расчёте границы снега NDSI используется облачная маска (Sentinel-2 SCL / Landsat QA_PIXEL): SCL 11 (снег/лёд) и Landsat snow-bit не маскируются.
- Изотермы выводятся из ERA5-Land с фиксированным температурным градиентом −6 °C/км и Copernicus DEM GLO-30. Это **приближённое масштабирование рельефом**, не температурные измерения и не надёжный прогноз для перевалов.
- Аналитические слои рассчитываются **по каждому спутниковому слою отдельно**. Для медианы изотермы рассчитываются **на первый день её интервала**, а не за все дни. Не смешивайте показатели при выводах о температуре.
- Точность и полнота слоёв зависят от доступности данных и прав аккаунта Earth Engine.
- Используются краткоживущие URL тайлов GEE: при восстановлении сессии/ZIP они выдаются заново. При длительной работе используйте кнопку «Обновить спутниковые тайлы».

## Проверка

```bash
python -m pytest tests -q
python -m compileall -q .
```

Тесты проверяют загрузку исходных KML, GPX, CSV и базовую геометрию. Нужна отдельная интеграционная проверка с реальным зарегистрированным проектом Google Earth Engine — без ключей GEE полный серверный расчёт проверить нельзя.
